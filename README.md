# nginx-lab
Лабораторная работа: построение сложных цепочек прокси.

## Задача

Есть несколько (N) nginx в режиме обратного прокси (proxy_pass...).
За ними приложение, отвечающее по HTTP.
Важно! Запрос от пользователя может прийти на любой из nginx
Запрос от пользователя может пройти как через один nginх, так и по цепочке через несколько nginx.
Примеры:

пользователь>nginx1>приложение
пользователь>nginx2>приложение
...
пользователь>nginxN>приложение
пользователь>nginx1>nginx2>nginxN>приложение
пользователь>nginx2>nginxN>приложение

Приложение проверяет заголовок X-Forwarded-For.
Требуется, чтобы приложение в заголовке получило IP адрес пользователя и всех nginx (всю цепочку), через которые прошел запрос.
Требуется, чтобы приложение не получило заголовок X-Forwarded-For, который недобросовестный пользователь может добавить в свой запрос.

## Решение

### Приложение

Лучшее приложение - то, которое не написано. Заголовки отдаются непосредственно средствами nginx.

### Цепочки

Наиболее простой и гибкий вариант цепного запроса для лабораторной работы - конструкция URL типа `http://nginx-lab-nginx-2/nginx-lab-nginx-1/nginx-lab-nginx-3/nginx-lab-nginx-3/`

nginx-2 перенаправляет на nginx-1 запрос `http://nginx-lab-nginx-1/nginx-lab-nginx-3/nginx-lab-nginx-3/` и так пока цепочка не закончится.

### Доверие и недоверие

Необходимо проверять заголовок на соответствие указанного адреса реальному. В nginx это делается нетривиально, тут я бы без ИИ не додумался. Сделано через map и regexp. Странно, но работает.

## Протокол тестирования

```
# docker compose run curl -H 'X-Forwarded-For: 192.168.1.1' http://nginx-lab-nginx-2/nginx-lab-nginx-1/nginx-lab-nginx-3/nginx-lab-nginx-3/
172.18.0.5, 172.18.0.2, 172.18.0.3
```

Как и ожидалось, 3 хопа.

## Масштабирование

На текущий момент, масштабирование требует изменения конфига nginx и docker-compose. Целесообразно было бы вынести nginx в отдельную сетку и сделать доверенность этой сети, а масштабирование осуществлять, например, посредством pulumi.
